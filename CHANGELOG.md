# Changelog

All notable changes to bussola are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org).

## [Unreleased]

### Added

- Compare two pieces of code: select lines by their numbers, choose **Compare with...**, select a second range in any unit or file of the review and choose **Compare with first range** to see them side by side with the changed words highlighted. Code moved or extracted elsewhere, also to another file, is found automatically: the two places are linked both ways with **moved to** and **moved from**, which open the comparison, and moves that kept the code unchanged are marked **identical**. Small and trivial blocks are left out ([#45](https://github.com/Spoki-App/bussola/issues/45)).
- Drag over the line numbers to select a range of lines: the selection follows the pointer, the page scrolls when it reaches the top or bottom edge, and the lines can then be approved with **Approve selection** or commented on, as with click and Shift+click. Dragging over the code still selects text to copy ([#43](https://github.com/Spoki-App/bussola/issues/43)).
- Every comment box (new thread, reply, file and review comment, editing a comment) has **Write** and **Preview** tabs and a formatting toolbar. **Preview** renders the draft exactly like a posted comment, with the same safety rules, and shows "Nothing to preview" when it is empty; the draft is kept when switching back. The toolbar adds headings (H1, H2, H3), bold, italic, strikethrough, inline code, code block, quote, link, bulleted, numbered and task lists: it wraps the selection or inserts a placeholder at the cursor, keeps the result selected so applying it again removes it, and can be undone with Cmd+Z (Ctrl+Z). Shortcuts: Cmd/Ctrl+B bold, Cmd/Ctrl+I italic, Cmd/Ctrl+K link, Cmd/Ctrl+E inline code and Cmd/Ctrl+Shift+P to toggle the preview; they never trigger the review shortcuts ([#37](https://github.com/Spoki-App/bussola/issues/37)).
- Shell tab completion for bash, zsh, fish and PowerShell: commands, options, paths for `--repo`, and local and remote branch names for the branch argument and `--base`, from the repository in the current folder or `--repo`. It only reads refs, never fetches, and offers no branches outside a repository. Set it up with `bussola --install-completion` or the line for your shell in the README ([#36](https://github.com/Spoki-App/bussola/issues/36)).
- Clicking a name in the diff highlights every occurrence of it in the same unit, on both sides of a split diff and in unified layout, without touching other units or files. Clicking another name moves the highlight, and clicking elsewhere or pressing Esc clears it. Cmd+click (Ctrl+click on Linux and Windows) still goes to the definition, and the color is **Occurrences of a name** in **Theme colors** ([#41](https://github.com/Spoki-App/bussola/issues/41)).
- Cmd+click (Ctrl+click on Linux and Windows) on a name imported from a framework or library, such as Django, React or the Go standard library, shows its documentation in the navigation popup: the full name, the signature and the docstring or doc comment, from the language server or, without one, read from the installed source of the library; the package and version installed for the repository; a link to the documentation page of that function, class or method when one can be built (Python standard library, Node.js, Go, React, Django, FastAPI, Flask, Requests, NumPy, pandas, lodash, Express, Read the Docs), kept apart from the package home; and **Open source** to read the file of the definition in the window. A name without a docstring still shows its signature, and when nothing is found the popup says so. Works for Python, TypeScript/TSX, JavaScript and Go ([#35](https://github.com/Spoki-App/bussola/issues/35)).
- Themes: **Theme** in **Settings** chooses System (the default), Light, Dark, a theme installed in VS Code, Cursor, Windsurf or VSCodium (listed automatically, with `include` followed) or a VS Code color theme imported from its `.json` file, applied to the whole interface, the diff and syntax highlighting. **Theme colors** changes single colors with a color picker or hex value, resets one or all of them, warns when text falls below WCAG AA contrast, and **Export as VS Code theme** saves the result. Only hex and rgb colors are read from imported files, and themes stay in the browser ([#39](https://github.com/Spoki-App/bussola/issues/39)).
- The code previews in the Cmd+click list of definitions and usages are colored like code on the review page, by the language of each file; files in a language the review does not highlight stay plain.
- Each usage in the **Usages of** list names the function, method or class it lives in, such as `whatsapp/utils.py:517 in Cart.total`, and usages outside any of them are labelled **module level**, for every language with go to definition ([#44](https://github.com/Spoki-App/bussola/issues/44)).
- The conversation panel can be hidden with the icon at its top right or with `t`, and the code takes its space. A thin bar stays on the right with the number of open threads and a button to show it again, also on narrow screens, where the panel opens over the code from the right. A comment not sent yet is kept while the panel is hidden. The choice is kept across reviews and after a reload, and replaces the **Show conversation** button of the review bar ([#47](https://github.com/Spoki-App/bussola/issues/47)).
- Changed words are found also when the modified line is not right next to its old version: each removed line of a block is paired with the most similar added line, so a line that gets a new comment above it still shows what changed. A renamed name marks only the part that changed (`_refresh_balance` to `refresh_credit_balance` marks `_` and `_credit`), and so does a name moved behind a module or object (`SELF_SERVE_V4_PLAN_SLUGS` to `settings.V4_PLAN_SLUGS` marks `SELF_SERVE_` and `settings.`), and added lines with no counterpart, such as the new comment, are marked whole. Lines that share less text are paired too, so a line rewritten around the same names, such as `self.key = f"...{self.account.id}"` to `self.key = PATTERN.format(account_id=self.account.id)`, shows what changed.
- **AI review** sends the whole pull request in one call with Claude Code and the Anthropic API, nothing clipped, and the same answer rates the impact of each unit, so the review starts at once instead of after a separate rating step. **Code per call** in **Settings** (`max_code_characters`) caps the code of one call for a model with a smaller context; OpenAI-compatible endpoints keep 100,000 characters unless it is set.
- **Settings** is laid out by category, with the categories (Pull requests, Repositories, Appearance, Diff and AI) on the left and their settings on the right. A search field at the top finds settings by name and description in every category and highlights the matches. The search has the focus when **Settings** opens, the arrow keys move between categories and Esc closes the window. Stored values are kept ([#46](https://github.com/Spoki-App/bussola/issues/46)).
- AI descriptions link to the lines they talk about: the model gets each line with its number and writes links such as `[the new check](#after-80)`, and clicking one opens the line in the unit's diff and highlights it, switching to the base diff for a line of the old version.
- The summary of an AI review in **Details** links to the lines it mentions, as `[text](#after:path:80)`: a click closes **Details** and scrolls the review to the line, highlighted, or opens the file when it is not part of the review.
- **AI prompts** in **Settings**: the instructions of **Describe**, **Rate impact** and **AI review** can be changed and reset to the default. bussola keeps its own part of each prompt (the input, the safety rule about instructions in the code, the tools and the answer format) and puts yours after it. They are saved in the `[ai.prompts]` section of `config.toml`, and a repository cannot change them.
- AI review of the whole pull request: **AI review** on the review page sends the changed units together, with the pull request description, the list of all changed units and the comments already made, so the model can see how the changes fit together. While it reviews, the model can follow the code like a reviewer in an editor: find where a name is defined or used (the same lookup as Cmd+click), read any file and search the repository at the reviewed commits, read-only and never in files the repository excludes from reviews. This works with the Anthropic API and OpenAI-compatible endpoints through tool calls, and with Claude Code through a local MCP server that lives only for the call. What it finds becomes threads anchored to the lines: AI threads show an **AI** badge and the provider and model as their author, can be resolved, replied to and deleted, follow new revisions like other threads, and are sent to GitHub by **Sync** with a line saying they were generated by the bussola AI review. Running it again reviews only the units changed since their last AI review, still with the rest of the pull request in view. **Review again** reviews every unit once more, keeping the threads already added. **Details** shows what each run did: the model's summary, the findings with a link to each thread, every code lookup with its result, the units reviewed and any error. The review page shows the progress (units done and total) and **Cancel** stops the run, keeping the findings already added ([#19](https://github.com/Spoki-App/bussola/issues/19)).
- While Cmd (Ctrl on Linux and Windows) is held, the name under the pointer is underlined, with a pointer cursor, when Cmd+click can take you somewhere, in the diff and in the window showing a file outside the review. Keywords, strings, comments, punctuation and names with no result are never underlined, and the underline goes as soon as the key is released or the pointer leaves the code. Each name is checked once, after the pointer rests on it, and a Cmd+click on it reuses that answer ([#40](https://github.com/Spoki-App/bussola/issues/40)).
- AI impact rating of each unit: a **Low**, **Medium** or **High impact** badge on the unit card with its one-line reason in the tooltip, marked outdated when a new revision changes the unit. **Rate impact** on the review page rates every unit without a current rating in a single request (a few for a very large pull request) and can be cancelled, keeping what was rated. The units can be filtered by impact and ordered with the highest impact first ([#18](https://github.com/Spoki-App/bussola/issues/18)).
- The window and tab title names the open review: `<project>#<number> <title>` for a pull request, such as `bussola#34 feat: AI description and impact rating of a unit, on demand`, and `<project> <branch>` for a branch. It follows the pull request title after a sync, and other pages keep `bussola` ([#50](https://github.com/Spoki-App/bussola/issues/50)).
- The AI provider can be chosen in **Settings**: provider, model, endpoint, key variable, timeout and answer budget are saved to the `[ai]` section of `config.toml` and take effect at once. Keys still come only from environment variables, and **Settings** saves only the name of the variable.
- **Describe** on each unit card asks the AI provider, in one call, what the unit does, what the change does to it and how much impact the change has (Low, Medium or High, with a one-line reason). The description is shown above the diff as Markdown, labelled with the provider and model, kept per unit version, marked outdated when a new revision changes the unit, and can be regenerated or cancelled while it runs ([#17](https://github.com/Spoki-App/bussola/issues/17)).
- The header of an open unit stays visible below the file header while you scroll through its diff, so its name and **Approve** stay at hand.
- Pluggable AI provider for the upcoming AI features: Claude Code CLI, Anthropic API or an OpenAI-compatible endpoint (Ollama, LM Studio), chosen in the `[ai]` section of the user configuration. A repository's `.bussola.toml` can only turn AI off; it can never turn AI on or choose where code is sent, because it arrives with the clone. Keys come only from environment variables. **Settings** shows the active provider and model and can test the connection. The building blocks for the AI actions are in place: an action button that stays hidden until a provider is configured and names the provider before code is first sent, schema-validated answers, timeouts and cancellation, batches with progress, and a result cache keyed by content hash, prompt version, system prompt and schema, and model ([#16](https://github.com/Spoki-App/bussola/issues/16)).
- Go to definition and find usages with Cmd+click (Ctrl+click on Linux and Windows) for Python, TypeScript/TSX, JavaScript and Go: a single result in the review scrolls to its line, others open in a list and, outside the review, in a window showing the file at the reviewed commit. A tree-sitter index of the repository works with nothing installed, and basedpyright, pyright, typescript-language-server or gopls are used when found on `PATH` ([#13](https://github.com/Spoki-App/bussola/issues/13)).
- Diff layout setting: split, unified or automatic, in **Settings** and in the review bar. Automatic splits units that rewrite lines when the window is at least as wide as a threshold set in **Settings** ([#10](https://github.com/Spoki-App/bussola/issues/10)).
- Changed words inside a modified line are highlighted with a stronger background on both the removed and the added line, when the two lines are similar enough ([#25](https://github.com/Spoki-App/bussola/issues/25)).
- Long lines in the diff wrap with a hanging indent and one line number per source line. Wrapping is on by default and can be turned off in Settings or with the wrap icon that appears at the bottom right of an open unit under the mouse; without wrapping, long lines stay on one row and the diff scrolls sideways, in split view each side on its own with its own scroll bar so the old and new lines stay aligned ([#11](https://github.com/Spoki-App/bussola/issues/11)).
- **Sync** marks as viewed on GitHub the files whose changes you have all approved. Partly approved files and files changed since approval are left alone, files already viewed are not touched, and a file that cannot be marked does not fail the sync ([#26](https://github.com/Spoki-App/bussola/issues/26)).
- `bussola://` links open the home page, a pull request review (started if needed), a file and line, highlighted, or a thread. In a pull request review, link icons copy a link to the review, a unit, a thread or, on hover, any line of the new version. A GitHub pull request link with `https` replaced by `bussola` works too. `bussola install-handler` registers the scheme on macOS, Linux and Windows, and a link starts the server when it is not running ([#20](https://github.com/Spoki-App/bussola/issues/20)).
- Unit names in card headers, methods included, and in the conversation panel start with their module (Python dotted module, TypeScript/JavaScript file path, Go package import path), muted, with the unit's own name in bold; long titles are cut at the start so the name stays visible, and a new box on the review page finds units by module, name or path ([#15](https://github.com/Spoki-App/bussola/issues/15)).

### Changed

- When only some units have an AI review, the two AI review buttons say how many units they send: **Review 12 units** for the units without one and **Review all 21** for the whole pull request, instead of **AI review** and **Review again** side by side.
- AI review comments start with the severity of the problem (🔴 Critical, 🟠 High, 🟡 Medium or 🔵 Low) and a one-line title, then say what is wrong, why it matters and how to fix it in short paragraphs, the fix after **Fix:**. The most severe findings are added first. The summary in **Details** is a one-sentence verdict followed by a short list of what was checked and found, and paragraphs in comments and descriptions have more space between them.
- Selecting lines to approve works like in an editor: a click selects only the clicked line, leaving none of the earlier ones selected, and Shift+click selects the lines from the last plain click to the clicked one. Consecutive Shift+clicks grow or shrink that range from the same line, in split and unified layout. Clicking the only selected line again clears the selection, and the selection is cleared when the diff changes, such as when switching between **Base → head** and **Approved → current** ([#42](https://github.com/Spoki-App/bussola/issues/42)).
- `bussola://` links start opening the browser in about a fifth of a second instead of half a second: the link handler no longer loads the web server, the database layer and FastAPI just to find the running server. Registered handlers keep working as they are.
- Lines are matched ignoring spaces, so code moved into a new block stays next to its old version in split view, with only the indentation it gained or lost highlighted at the start of the line, instead of showing as a block removed and a different block added. In such a block the lines added or removed with no counterpart are highlighted in full.
- Cmd+click with a single result outside the review opens the file in a window at once, instead of a list with one entry.
- The unit filter (All, To review, Since my last review) is kept in this browser, so a reload or a new tab opens with the last choice, as the diff layout already did.
- The unit filter, the search box and the diff layout switch sit at the top of the **Files** bar, so they stay visible while you scroll the units. With the **Files** bar hidden they are above the units.
- Allow tree-sitter 0.26. Syntax tree positions are read as plain tuples, because the `Point.row` and `Point.column` properties in tree-sitter 0.26.0 drop a reference on every read and crash the process on files longer than 256 lines.

### Fixed

- Cmd+click on a Python class attribute where it is assigned, such as `BLOCKED_DETAIL = (...)` in a class body, lists where it is used. It was taken for a use of the name and went to the assignment itself.
- Cmd+click on a plain name, such as a call to `_kind(...)`, lists only its definition in the same file when the file has one. Before the language server was ready, functions with the same name in other files were listed too. A name after a dot, such as `other._kind()`, still lists every definition with that name.
- Unit cards no longer scroll on their own when the mouse wheel is over them. The button that copies a link to a line stuck out one pixel below the last line, which gave each card a vertical scrollbar.
- Added and removed lines and changed words use the dark theme colors in dark mode. The light theme colors were applied instead and were hard to see.
- Text selected in the diff is readable in dark mode. It was shown on the light blue selection background of the light theme.
- **Approve file** no longer skips units whose content matches a unit already approved in another file, such as test classes with the same header. They were taken for approvals moved from that file and left as New.
- The first requests after starting with a new database no longer fail with a server error when several arrive at once and all try to add the same reviewer.
- Comments on the whole review, including pull request comments and review summaries imported from GitHub, no longer have a Resolve button and no longer count as open threads, as on GitHub.
- Expressions inside Python f-strings and JavaScript/TypeScript template literals are highlighted as code instead of string, with the braces, conversions and format specs set apart ([#21](https://github.com/Spoki-App/bussola/issues/21)).
- Below 700px wide, the Files list sits above the units again instead of covering the whole page, and unit headers wrap as intended. The narrow-screen styles were overridden by base rules declared after them.

## [0.1.0] - 2026-10-30

First public release.

### Added

- Local review UI (`bussola serve`) and the `bussola status` and `bussola refresh` commands.
- Changes split into functions, methods, classes, types, module-level code and whole files, with tree-sitter parsing for Python, TypeScript, TSX, JavaScript and Go.
- Approvals tied to unit content, kept across new commits, rebases and renames, and approval of selected lines in module-level code and whole files.
- "Since my last review" filter, revisions, and diffs from the approved version to the current one.
- Comment threads anchored to lines that follow the code across revisions, including resolved threads.
- GitHub pull request reviews through the `gh` CLI: listing, opening from a link, importing and syncing comments, sending comments as a pull request review, and resolving threads.
- GitHub-style rendering of comments and descriptions, with alerts, mermaid diagrams and attached images.
- Syntax highlighting, image diffs, a collapsible file tree and code font settings.
